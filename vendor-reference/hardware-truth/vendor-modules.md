## DT compatibles and modaliases

* Embedded module aliases found only for `tsi721_mport` (PCI), `virtio_crypto` (virtio), `zx_ponreg` (platform), and `usb-storage` (391 USB aliases).
* No literal OF `alias=of:...` records were present. `np` and `plat_132` nevertheless import OF matching/compatibility routines, so their compatible strings are likely runtime tables or compared strings; strings evidence should be treated as candidate-only unless tied through relocation/disassembly.
* ULPI synthesizes modaliases dynamically (`MODALIAS=ulpi:v%04xp%04x`) and uses OF device modalias helpers.

## Reverse-engineering evidence and limitations

* IDA databases exist for `usb_led`, `bspdriver`, `np`, `plat_132`, `switch`, `zx279051`, and `rtl8373_switch` beside the modules.
* Existing recovered documentation is concentrated in `docs/reverse-engineering/plat_132/`, especially `FUNCTIONS.md`, `MEMORY.md`, `CALLBACK_INTERFACES.md`, and recovered `plat_probe.c`, `plat_irq.c`, `plat_timer.c`, `plat_nppt.c`, `plat_smac.c`, `plat_idm.c`, `plat_cpu_net.c`. It corroborates PON/NPPT interrupts, clocks/resets, APB/UNI SerDes accesses, timer MMIO, MDIO/PHY, and netdev/IDM paths.
* Confidence rubric: **High** = modinfo, undefined import, exported symbol, loaded snapshot, or explicit string/path; **Medium** = strongly named internal/exported routine without direct call-site proof; **Low** = numeric ABI inference not asserted.

## Globally absent or unproven

No module imports Linux regulator, generic power-domain/genpd, IOMMU, OPP, interconnect, or thermal frameworks. No `debugfs_*` creation was found. Generic PHY framework use is absent; “PHY” activity is vendor Ethernet PHY/MDIO logic. DMA API use is proven only for `tsi721_mport` and USB/SCSI buffer paths in `usb-storage`; direct physical-address/ring manipulation in vendor datapath modules may bypass generic DMA APIs. The five discovered ioctl handlers are resolved in `ioctls.md`; `switch.ko`'s netdev ioctl is a no-op.
